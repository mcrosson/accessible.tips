# accessible.tips — orientation

## Purpose and shape

A Hugo static site that is a zettelkasten-style accessibility knowledge base: short, cross-referenced tips with separate anecdotes, FAQ, and dated news. Content is predominantly Markdown; presentation and behavior live in a heavily customized `hugo-xmin` theme plus a `hugo-admonitions` component. Deployed via Netlify. Licensed CC BY-SA 4.0. [anchor: README.md, LICENSE, config.toml, netlify.toml]

The active content roots are `content/tips/`, `content/anecdotes/`, `content/faq/`, `content/news/`. The contributing FAQ refers to a `posts/` directory that does not exist — the real blog is `news/`. Each section has a `_test/` fold with a likely-draft `index.md` — check before assuming a section is empty. [anchor: config.toml, content/faq/contributing.md, content/]

## Front matter and content contracts

Archetypes in `archetypes/` are the source of truth for page scaffolding. Tips/faq/anecdotes carry a front-matter `changelog` (list of `{date, text}`); `single.html` renders that automatically as `<h2 id="changelog">`, so do NOT add a hand-written `## Changelog` heading in body text — it duplicates. The "Updated" masthead date is the newest changelog entry (sorted desc), not `lastMod`/`GitInfo` — `enableGitInfo` is off and there is no `lastMod` override, so "Updated" tracks the changelog only. [anchor: archetypes/, themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/_partials/util/changelog-latest.html, config.toml]

Anecdotes MUST have BOTH `categories: [anecdote]` AND `tags: [anecdote]` — the *section* (`eq .Section "anecdotes"`) flips the triggering-content warning in `page_meta.html`; the tag is the search/related hook. FAQ pages are tagged `faq` only — adding other tags ties FAQ into the main knowledge base, which is undesired. News pages are intentionally untagged for the same reason. Tips carry a single primary category; filenames conventionally begin with that category (e.g. `medications-mmj-blocked-carts.md`). Use page bundles (`directory/index.md`) when a page owns images or downloads. [anchor: content/faq/contributing.md, themes/hugo-xmin/layouts/_partials/page_meta.html, content/tips/]

One optional search-only front matter: `search_terms` — terms that should be findable but never appear in the body (e.g. intentional brand misspellings). It is emitted as a Pagefind `data-pagefind-meta` span and folded into the corrector vocabulary, but it is NOT a tag and does NOT feed related. Synonym clusters belong in `data/equiv.toml`. [anchor: archetypes/, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/index.searchvocab.json, data/equiv.toml]

Content structure is part of the reading UX: `{{< back_to_top >}}` after every level-2 heading, `{{< end_section >}}` at the end of deeper sections. Cross-references use Hugo `ref` shortcodes with `[category]-[file]` (tips) / `section/file` (faq/anecdotes). The `figure` shortcode is required for images — it generates responsive WebP variants at 400w/800w/1200w and wraps the 1200w in a Tobii lightbox runtime that is lazy-loaded only when a `<figure>` is near the viewport. [anchor: content/faq/contributing.md, themes/hugo-xmin/layouts/shortcodes/figure.html, themes/hugo-xmin/assets/js/tobii-lazy-shim.js, themes/hugo-xmin/layouts/_partials/footer.html]

## Rendering pipeline

`hugo-xmin` is heavily modified from upstream — treat `themes/hugo-xmin/` as application code (the upstream README in that dir is stale). `single.html` composes header, metadata, the searchable `<main data-pagefind-body>` (equivalence injection + filter declarations + `.Content` + auto-changelog), and footer. Related pages use Hugo's built-in `.CurrentSection.RegularPages.Related` with a default cap of 5. `hugo-admonitions` supplies the blockquote-alert markup and its Sass — keep the two themes in lock-step when touching admonitions. Goldmark has `unsafe = true`, so raw HTML in pages is rendered (and IS indexed by Pagefind). [anchor: themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/related.html, themes/hugo-xmin/layouts/_partials/_has_related.html, themes/hugo-admonitions/, config.toml]

Search is a post-build concern. Pagefind writes its bundle to `/pagefind/` in the output dir; that is why every search query must be served over HTTP (`file://` returns nothing) and why `bin/dev.sh` is search-inert. `/search-vocab.json` is a build-time corrector vocabulary, generated by the custom `index.searchvocab.json` output format (per `config.toml` `[outputFormats.searchvocab]` + `[outputs].home`). `data/equiv.toml` defines hand-curated synonym classes; each class is a list of members. The same computation lives in the shared partial `equiv-page-inject.html` (haystack = title + body + tags + search_terms; normalize: lowercase + collapse `[-_/\s]+` to a single space, `\b` word boundaries; no singularizer — add `s`/`es` variants as explicit members). The injection partial renders this set as hidden `display:none` in-body text inside `data-pagefind-body` (verified against the vendored Pagefind 1.5.2 — its static HTML parser does NOT skip CSS-hidden in-body text); the `index.searchvocab.json` template folds the same set into the corrector vocabulary. [anchor: bin/build.sh, themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/assets/js/search-page.js, themes/hugo-xmin/layouts/index.searchvocab.json, themes/hugo-xmin/layouts/_partials/equiv-inject.html, themes/hugo-xmin/layouts/_partials/equiv-page-inject.html, themes/hugo-xmin/layouts/_partials/search-filters.html, data/equiv.toml]

The `/search/` page is submit-only: no keystroke handler, the first `/pagefind/` request fires on Enter or the Search button. The corrector (`corrector.js`) is SUGGEST-ONLY — it never alters the query Pagefind receives; it computes a clickable "Did you mean …?" via per-token Damerau–Levenshtein (MAX_DISTANCE=2, MIN_TOKEN_LEN=4) against the build-time vocabulary, deterministic tiebreak (smaller distance → higher df → shorter term → lexicographic). Facets are `section` and `tag` (checkbox, OR within a facet, AND across), state in the URL as repeated keys, the panel auto-opens when selections are active. Plausible is hardcoded in the header with `data-domain="kb.accessible.tips"`. The theme toggle is a single cycling `<button>` (auto→light→dark→auto) that persists only `light`/`dark` to `localStorage["theme"]`; auto = key absent, and the header's anti-FOUC inline snippet applies the override before first paint. The orphan User-Agent `CCBot` is disallowed in `robots.txt`. [anchor: themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/assets/js/search-page.js, themes/hugo-xmin/assets/js/corrector.js, themes/hugo-xmin/assets/js/theme-toggle.js, themes/hugo-xmin/layouts/_partials/header.html, themes/hugo-xmin/layouts/_partials/theme-toggle.html, themes/hugo-xmin/layouts/robots.txt]

## Build and deployment

The pipeline is intentionally self-contained — vendored binaries, zero Node. `bin/build.sh [output-dir]` runs Hugo 0.155.3 with `--gc --minify` then Pagefind over the rendered HTML. A *relative* output-dir is resolved against the repo root (the script `cd`s there); pass an absolute path (e.g. `/tmp/site-build`) to output where you stand. Pagefind runs AFTER Hugo and indexes files on disk — `--renderToMemory` is NOT compatible with `bin/build.sh`. Netlify publishes `public/` via `bin/build.sh`; production TZ is in `netlify.toml`. The empty `Staticfile` at the repo root is legacy (Cloud Foundry) and is not the active deploy target. [anchor: bin/build.sh, netlify.toml, Staticfile, config.toml, bin/hugo-0.155.3, bin/pagefind]

For ordinary editing, `bin/dev.sh [port]` runs Hugo's dev server with `--renderToMemory --disableFastRender -D` — fast live reload, but `/search/` is inert because Pagefind is never run. Use `bin/preview.sh` for a real HTTP, searchable build: working-dir mode (default, or numeric port) builds the current uncommitted-on-disk tree into `${TMPDIR:-/tmp}/accessible-tips-preview` via `bin/build.sh` and serves with `python3 -m http.server` — `git status` stays clean, `public/` is never touched. A NON-numeric first argument is a branch name; `preview.sh` creates a *detached* linked worktree at `<repo>/_preview` at that branch, builds there, and serves. Both modes stop with Ctrl-C. `bin/end-preview.sh [port]` is idempotent: kills the server on the port, removes the `_preview` worktree, removes the scratch dir. It deliberately does NOT run a blanket `git worktree prune` (which can clobber unrelated worktrees invisible in this mount namespace). [anchor: bin/dev.sh, bin/preview.sh, bin/end-preview.sh]

## High-risk maintenance points

Site-wide behavior lives in `config.toml` and the customized `hugo-xmin` layouts/partials, particularly `header.html`, `page_meta.html`, `single.html`, `search.html`, `search-page.js`, `corrector.js`, `theme-toggle.html`, `style.css`. The `Decap` web editor is documented in the FAQ for "later use" but is NOT currently wired up — do not reintroduce it (or `Static CMS`, removed 2024-07). Generated output in `public/` is git-ignored; do not hand-edit it. Use the vendored binaries; assume no system Hugo or Node toolchain. [anchor: config.toml, content/faq/tech-used.md, content/news/2024-07-04-updates.md, .gitignore]

When changing search, test with `bin/preview.sh` over HTTP — `bin/dev.sh` is silent there and `file://` is misleading. A typo in `data-pagefind-filter` or moving a member in `data/equiv.toml` is silent without HTTP preview — verify both rendered metadata AND facets/equivalence behavior. When editing templates, preserve accessibility details: alt text, ARIA labels, live regions, focus visibility, the `u-visually-hidden` helper, and the admonition markup that the accessibility-focused site depends on. [anchor: bin/preview.sh, themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/assets/js/search-page.js, LICENSE, README.md]
