# accessible.tips — orientation

## Purpose and shape

Hugo static site: zettelkasten-style accessibility knowledge base — short, cross-referenced tips with separate anecdotes, FAQ, and dated news. Presentation lives in a heavily customized `hugo-xmin` plus a vendored `hugo-admonitions` component. Deployed via Netlify. CC BY-SA 4.0. **Accessibility IS the product** — WCAG AA floor, AAA free/cheap; low-bandwidth is a hard requirement (Hugo `--minify`, responsive WebP via `figure` shortcode, lazy lightbox runtime). [anchor: README.md, LICENSE, config.toml, netlify.toml]

Content roots: `content/tips/`, `content/anecdotes/`, `content/faq/`, `content/news/`. The contributing FAQ still references a non-existent `posts/` — the real blog is `news/`. Each section has a `_test/index.md` (likely draft) exercising section-specific behavior; check before assuming a section is empty. [anchor: content/faq/contributing.md, content/]

## Front matter and content contracts

Archetypes in `archetypes/` are the scaffolding source of truth. Tips/FAQ/anecdotes carry a `changelog` list of `{date, text}`; `single.html` auto-renders it as `<h2 id="changelog">` AFTER `.Content` — do NOT hand-write `## Changelog` in body. The "Updated" masthead date is the newest changelog entry (sorted desc), NOT `lastMod`/`GitInfo` — `enableGitInfo` is OFF and there is no `lastMod` override, so "Updated" tracks the changelog only. The shared helper `partials/util/changelog-latest.html` returns the raw date; each caller applies its own `dateFormat`. [anchor: archetypes/, themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/_partials/util/changelog-latest.html, config.toml]

The anecdotes WARNING banner is gated by `eq .Section "anecdotes"` in `page_meta.html` (section membership, NOT a front-matter category check — the contributing FAQ's instruction to use `categories: [anecdote]` is unenforced in practice; the section check is what actually triggers the warning). FAQ is tagged `faq` only; news is intentionally untagged — adding tags ties them into the main knowledge base, undesired. Tips carry a single primary category; filenames conventionally begin with that category. Use page bundles (`directory/index.md`) when a page owns images or downloads. [anchor: content/faq/contributing.md, themes/hugo-xmin/layouts/_partials/page_meta.html, content/anecdotes/]

One optional search-only front-matter: `search_terms` — terms the page should be findable by that the body never names. Emitted as a Pagefind `data-pagefind-meta` span AND folded into the corrector vocabulary. NOT a tag; does NOT feed related. Synonym clusters belong in `data/equiv.toml`. [anchor: archetypes/, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/index.searchvocab.json, data/equiv.toml]

Content structure is part of the reading UX: `{{< back_to_top >}}` after every H2, `{{< end_section >}}` at the end of deeper sections. Cross-references use Hugo `ref` shortcodes (`[category]-[file]` for tips, `section/file` for faq/anecdotes). The `figure` shortcode is required for images — 400w/800w/1200w responsive WebP, the 1200w wrapped in a Tobii lightbox trigger. The lightbox runtime is loaded only when a `<figure>` is near the viewport (`tobii-lazy-shim.js`); `tobii-a11y-overrides.js` sets `inert` on `<main>`/`<article>` while open, so image-less pages pay zero JS cost. [anchor: content/faq/contributing.md, themes/hugo-xmin/layouts/shortcodes/figure.html, themes/hugo-xmin/assets/js/tobii-lazy-shim.js, themes/hugo-xmin/assets/js/tobii-a11y-overrides.js]

## Rendering pipeline

Treat `themes/hugo-xmin/` as application code (the in-theme README is stale). `single.html` composes header, metadata, the searchable `<main data-pagefind-body>` (equiv-inject + filter declarations + `.Content` + auto-changelog), and footer. Related pages use Hugo's built-in `.CurrentSection.RegularPages.Related`; `_has_related.html` sets a scratch flag when at least one exists, so consumers only render the block when there is something to link. `hugo-admonitions` is vendored (`themes/hugo-admonitions/VENDOR.md` lists the pin and the one sanctioned direct edit — `aria-hidden` on icon `<svg>`s); register it left-most in `config.toml` so it wins any blockquote-render-hook overlap. Goldmark `unsafe = true` — raw HTML in pages renders AND is indexed by Pagefind. [anchor: themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/related.html, themes/hugo-xmin/layouts/_partials/_has_related.html, themes/hugo-admonitions/, config.toml]

Search is a post-build concern. Pagefind writes its bundle to `/pagefind/` in the output dir — every query must be served over HTTP (`file://` returns nothing) and `bin/dev.sh` is search-inert. `/search-vocab.json` is a build-time corrector vocabulary, generated by the custom `index.searchvocab.json` output format; `data/search/stopwords.yaml` is applied during vocabulary generation. `data/equiv.toml` defines hand-curated synonym classes. The SAME per-page equivalence computation lives in the shared partial `equiv-page-inject.html` (haystack = title + body + tags + search_terms; class match by `\b` word boundaries on a normalized lowercase form; no singularizer — add `s`/`es` variants as explicit members). It returns a slice; `equiv-inject.html` renders it as hidden in-body text inside `data-pagefind-body` (Pagefind 1.5.2's static parser does NOT skip CSS-hidden in-body text), and `index.searchvocab.json` folds the same slice into the corrector vocabulary. ONE computation, two consumers — they cannot drift. [anchor: themes/hugo-xmin/layouts/index.searchvocab.json, themes/hugo-xmin/layouts/_partials/equiv-inject.html, themes/hugo-xmin/layouts/_partials/equiv-page-inject.html, data/equiv.toml, data/search/stopwords.yaml, config.toml]

The `/search/` page is submit-only; the first `/pagefind/` request fires on Enter or the Search button. The corrector (`corrector.js`) is SUGGEST-ONLY — never alters the query Pagefind receives; per-token Damerau–Levenshtein (`MAX_DISTANCE=2`, `MIN_TOKEN_LEN=4`), deburr-fold + lowercase, deterministic tiebreak (smaller distance → higher df → shorter term → lexicographic). The Pagefind runtime is loaded via `new Function("src", "return import(src)")` so esbuild does not try to bundle a file absent at build time. Facets are `section` and `tag` (OR within a facet, AND across), state in the URL as repeated keys; the panel auto-opens when selections are active. The theme toggle is a single cycling `<button>` (auto→light→dark→auto) persisting only `light`/`dark` to `localStorage["theme"]`; auto = key absent; the header's anti-FOUC inline snippet applies any override before first paint. The button ships with `hidden` and is revealed only after JS runs. Plausible is hardcoded with `data-domain="kb.accessible.tips"`. `CCBot` is disallowed in `robots.txt`. [anchor: themes/hugo-xmin/assets/js/search-page.js, themes/hugo-xmin/assets/js/corrector.js, themes/hugo-xmin/assets/js/theme-toggle.js, themes/hugo-xmin/layouts/_partials/header.html, themes/hugo-xmin/layouts/_partials/theme-toggle.html, themes/hugo-xmin/layouts/robots.txt]

## Build and deployment

Self-contained — vendored binaries, zero Node. `bin/build.sh [output-dir] [cache-dir]` runs Hugo 0.155.3 with `--gc --minify` then Pagefind. A *relative* `output-dir` is resolved against the repo root; pass an absolute path (e.g. `/tmp/site-build`) to output where you stand. The optional `cache-dir` second argument routes Hugo's `--cacheDir` to a per-instance directory; concurrent builds MUST each pass their own cache dir, or they race on the shared cache at the repo root. Pagefind indexes files on disk AFTER Hugo — `--renderToMemory` is NOT compatible. Netlify publishes `public/` via `bin/build.sh`; production TZ (`US/Eastern`) lives in `netlify.toml`. The empty `Staticfile` is legacy (Cloud Foundry), not the active deploy target. [anchor: bin/build.sh, netlify.toml, Staticfile, bin/hugo-0.155.3, bin/pagefind]

`bin/dev.sh [port]` runs Hugo's dev server with `--renderToMemory --disableFastRender -D` and a per-port Hugo cache dir (`${TMPDIR:-/tmp}/accessible-tips-dev-$PORT/hugo-cache`). An optional first arg is parsed as a port (all-numeric → port, anything else → passes through to `hugo server`); remaining args forward. Live-reload works; `/search/` is INERT — use `bin/preview.sh` for real HTTP, searchable builds. [anchor: bin/dev.sh]

`bin/preview.sh [port|branch [port]]` has two modes, dispatched by whether the first arg is numeric. WORKING-DIR mode (default, or all-numeric port) builds the current on-disk tree (uncommitted changes included) into `${TMPDIR:-/tmp}/accessible-tips-preview-$PORT` via `bin/build.sh` and serves with `python3 -m http.server`. `git status` stays clean, `public/` is never touched, and each port gets its own out-of-repo scratch dir + per-instance Hugo cache. WORKTREE/BRANCH mode (non-numeric first arg) creates a *detached* linked worktree at `<repo>/_preview-$PORT` (port-keyed so concurrent branch previews don't collide), builds there, and serves that. Both modes serve over real HTTP (Pagefind needs it; `file://` is silent). Default port 1313. `bin/end-preview.sh [port]` is idempotent: kills the server on the port (best-effort), removes the `_preview-$PORT` worktree, removes the scratch dir. It deliberately does NOT run a blanket `git worktree prune` (can clobber unrelated worktrees invisible in the current mount namespace) — only touches `_preview-$PORT` by exact path. [anchor: bin/preview.sh, bin/end-preview.sh]

## High-risk maintenance points

Site-wide behavior lives in `config.toml` and the customized `hugo-xmin` layouts/partials, particularly `header.html`, `page_meta.html`, `single.html`, `search.html`, `search-page.js`, `corrector.js`, `theme-toggle.html`, `style.css`. `Decap` is documented in the FAQ for "later use" but is NOT currently wired up — do not reintroduce it (or `Static CMS`, removed 2024-07). `public/` is gitignored stale output — never hand-edit, never regenerate as a deliverable. Use the vendored binaries; assume no system Hugo or Node toolchain. [anchor: config.toml, content/faq/tech-used.md, content/news/2024-07-04-updates.md, .gitignore]

When changing search, test with `bin/preview.sh` over HTTP — `bin/dev.sh` is silent there and `file://` is misleading. A typo in `data-pagefind-filter` or a moved `data/equiv.toml` member is silent without HTTP preview — verify both rendered metadata AND facets/equivalence behavior. When editing templates, preserve accessibility details: alt text, ARIA labels, live regions, focus visibility, the `u-visually-hidden` helper, the `aria-hidden` + `focusable="false"` on admonition icons, and the lightbox `inert` toggle on `<main>`/`<article>`. The repo-local testing skills (`.agents/skills/`) — site-browser, smoke-test, a-b-compare, a11y-audit — are all Playwright-driven and all vision-required. Test artifacts go under `.scratch/test-artifacts/` (gitignored).
