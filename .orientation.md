# accessible.tips — orientation

## Purpose and shape

A Hugo static site that is a zettelkasten-style accessibility knowledge base: short, cross-referenced tips grouped by tags, with separate anecdotes, FAQ, and dated news. Content is predominantly Markdown; presentation and behavior live in a heavily customized `hugo-xmin` theme plus a small `hugo-admonitions` plugin. [anchor: README.md, config.toml, content/]

The active content roots are `content/tips/`, `content/anecdotes/`, `content/faq/`, and `content/news/`. The contributing FAQ refers to a `posts/` directory that does not exist — the real blog is `news/`. Permalinks are configured per section and news URLs carry their date. [anchor: config.toml, content/, content/faq/contributing.md]

## Front matter and content contracts

The archetypes in `archetypes/` are the source of truth for page scaffolding. Tips/faq/anecdotes carry a front-matter `changelog` (list of `{date, text}`); `single.html` renders that automatically as a `<h2 id="changelog">` block, so do NOT add a hand-written `## Changelog` heading in body text — it duplicates. Updated date in the masthead is the newest changelog entry (newest determined by sort, not by `lastMod`/`GitInfo`). The repo currently has `enableGitInfo` disabled and no `lastMod` override, so "Updated" tracks the changelog only. [anchor: archetypes/, themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/_partials/util/changelog-latest.html, config.toml]

Anecdotes require BOTH `categories: [anecdote]` AND `tags: [anecdote]` — the category flips the triggering-content warning in `page_meta.html` (`{{ if eq .Section "anecdotes" }}`); the tag is the search/related hook. FAQ pages are tagged `faq` only — adding other tags ties FAQ into the main knowledge base, which is explicitly undesired. News pages are intentionally untagged (same reason). Tips carry a single primary category; filenames conventionally begin with that category (e.g. `medications-mmj-blocked-carts.md`). Use page bundles (`directory/index.md`) when a page owns images or downloads. [anchor: content/faq/contributing.md, content/tips/, content/anecdotes/, themes/hugo-xmin/layouts/_partials/page_meta.html]

There is one optional search-only front matter: `search_terms` — terms that should be findable but never appear in the body (e.g. intentional brand misspellings). It is emitted as a Pagefind meta field and contributes to the corrector vocabulary, but it is NOT a tag and does NOT feed related. Synonyms belong in `data/equiv.toml`, not here. [anchor: archetypes/, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/index.searchvocab.json]

Content structure is part of the reading UX: place `{{< back_to_top >}}` after every level-2 heading and `{{< end_section >}}` at the end of deeper sections. Cross-references use Hugo `ref` shortcodes with the `[category]-[file]` (tips) / `section/file` (faq/anecdotes) basename convention. The `figure` shortcode is required for images — it generates responsive WebP variants of page-bundle resources at 400w/800w/1200w and wraps the 1200w in a Tobii lightbox; the lightbox runtime is lazy-loaded by the browser only when a figure is near the viewport. [anchor: content/faq/contributing.md, themes/hugo-xmin/layouts/shortcodes/figure.html, themes/hugo-xmin/assets/js/tobii-lazy-shim.js, themes/hugo-xmin/layouts/_partials/footer.html]

## Rendering pipeline

`hugo-xmin` is not pristine upstream — treat `themes/hugo-xmin/` as application code. `single.html` composes header, metadata, the searchable `<main data-pagefind-body>` (which contains equivalence injection + filter declarations + `.Content` + the auto-changelog), and footer. Related pages use Hugo's built-in `.Related` over `.CurrentSection.RegularPages`, defaulting to 5 results. `hugo-admonitions` supplies the blockquote-alert markup and its Sass styling — keep the two themes in lock-step when touching admonitions. Goldmark has `unsafe = true`, so raw HTML in pages is rendered (and IS indexed by Pagefind). [anchor: themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/related.html, themes/hugo-admonitions/layouts/_default/_markup/render-blockquote-alert.html, config.toml]

Search is a post-build concern. Pagefind writes its bundle to `/pagefind/` in the output dir; that is why every search query must be served over HTTP (`file://` returns nothing) and why `bin/dev.sh` is search-inert. `/search-vocab.json` is a build-time corrector vocabulary, generated by the custom `index.searchvocab.json` output format (per `config.toml` `[outputFormats.searchvocab]` + `[outputs].home`). `data/equiv.toml` defines hand-curated synonym classes; each class is a list of members, the injection partial normalizes both haystack (title + body + tags + search_terms) and members (lowercase, collapse `[-_/\s]+` to a single space), and any page matching one member gets the others injected as hidden `display:none` text inside `data-pagefind-body` (verified against Pagefind 1.5.2 — its static HTML parser does NOT exclude CSS-hidden in-body text). There is no singular/plural normalizer; add `s`/`es` variants as explicit members. The same computation is shared with the corrector vocabulary so the two never drift. [anchor: bin/build.sh, themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/layouts/index.searchvocab.json, themes/hugo-xmin/layouts/_partials/equiv-inject.html, themes/hugo-xmin/layouts/_partials/equiv-page-inject.html, themes/hugo-xmin/layouts/_partials/search-filters.html, data/equiv.toml]

The `/search/` page is submit-only: no keystroke handler, type→fetch suppressed, first Pagefind request fires on Enter or the Search button. The orphan User-Agent `CCBot` is disallowed in robots.txt. Plausible is hardcoded in the header with `data-domain="kb.accessible.tips"`. The theme toggle is a single cycling `<button>` (auto→light→dark→auto) that persists only `light`/`dark` to `localStorage["theme"]`; auto = key absent, and the header's anti-FOUC inline snippet applies the override before first paint. Three SVG icons (distinct shapes, not just colour) are pre-shipped in markup and CSS reveals only the one matching `data-mode`. [anchor: themes/hugo-xmin/layouts/_partials/header.html, themes/hugo-xmin/layouts/_partials/theme-toggle.html, themes/hugo-xmin/assets/js/search-page.js, themes/hugo-xmin/assets/js/theme-toggle.js, themes/hugo-xmin/layouts/robots.txt]

## Build and deployment

The pipeline is intentionally self-contained — vendored binaries, zero Node. `bin/build.sh [output-dir]` runs Hugo 0.155.3 with `--gc --minify` then Pagefind over the rendered HTML. A relative output-dir is resolved against the repo root (the script `cd`s there); pass an absolute path (e.g. `/tmp/site-build`) to output where you stand. Pagefind runs AFTER Hugo and indexes files on disk — `--renderToMemory` is not compatible with `bin/build.sh`. Netlify publishes `public/` via `bin/build.sh`; production TZ is set in `netlify.toml`. The `Staticfile` at the repo root is empty/legacy (Cloud Foundry) and is not the active deploy target. [anchor: bin/build.sh, netlify.toml, Staticfile, config.toml, bin/hugo-0.155.3, bin/pagefind]

For ordinary editing, `bin/dev.sh [port]` runs Hugo's dev server with `--renderToMemory --disableFastRender -D` — fast live reload, but `/search/` is inert because Pagefind is never run. Use `bin/preview.sh` for a real HTTP, searchable build: working-tree mode (default, no args, or numeric port) builds the current uncommitted-on-disk tree into `${TMPDIR:-/tmp}/accessible-tips-preview` via `bin/build.sh` and serves with `python3 -m http.server` — `git status` stays clean, `public/` is never touched. A NON-numeric first argument is a branch name; preview.sh creates a *detached* linked worktree at `<repo>/_preview` at that branch, builds there, and serves. Both modes stop with Ctrl-C. `bin/end-preview.sh [port]` (idempotent) kills the server on the port, removes the `_preview` worktree, and removes the scratch dir; it deliberately does NOT run a blanket `git worktree prune` (which can clobber unrelated worktrees invisible in this mount namespace). [anchor: bin/dev.sh, bin/preview.sh, bin/end-preview.sh]

## High-risk maintenance points

Site-wide behavior lives in `config.toml` and the customized `hugo-xmin` layouts/partials, particularly `header.html`, `page_meta.html`, `single.html`, `search.html`, `search-page.js`, `corrector.js`, `theme-toggle.html`, `style.css`. The `Decap` web editor is documented in the FAQ for "later use" but is NOT currently wired up — do not assume CMS-driven edits, and do not reintroduce `Static CMS` (it was removed in 2024-07). Generated output lives in `public/` and is git-ignored; do not hand-edit it. Use the vendored binaries; assume no system Hugo or Node toolchain. [anchor: config.toml, content/faq/tech-used.md, content/news/2024-07-04-updates.md, .gitignore, bin/]

When changing search, test with `bin/preview.sh` over HTTP — `bin/dev.sh` is silent there and `file://` is misleading. When changing front matter, verify rendered metadata AND search facets/equivalence behavior (a typo in `data-pagefind-filter` or moving a member in `data/equiv.toml` is silent without HTTP preview). When editing templates, preserve accessibility details: alt text, ARIA labels, live regions, focus visibility, the `u-visually-hidden` helper, and the admonition markup that the accessibility-focused site depends on.
