# accessible.tips — orientation

## Purpose and shape

This is a Hugo static site forming a zettelkasten-style accessibility knowledge base: focused tips are cross-referenced and related by tags, with separate anecdotes, FAQ, and dated news sections. Content is predominantly Markdown; presentation and behavior are in the vendored, customized themes. [anchor: README.md, config.toml, content/]

The active content roots are `content/tips/`, `content/anecdotes/`, `content/faq/`, and `content/news/`; do not confuse the legacy/editorial term “posts” with the actual `news` directory. Permalinks are configured per section, with news dates in URLs. [anchor: config.toml, content/]

## Content contracts

Use the archetypes and existing pages as the source of truth for front matter. Normal pages generally carry title, authors, date fields, `toc`, `draft`, categories, tags, and a front-matter `changelog`; the single-page template renders that changelog automatically, so adding a hand-written `## Changelog` duplicates it. Update `lastMod` and add a changelog entry when editing. [anchor: archetypes/, content/tips/, content/faq/, themes/hugo-xmin/layouts/single.html]

Tips use a single primary category and filenames conventionally begin with that category. FAQ pages are tagged `faq`; news pages intentionally have no tags. Anecdotes require both `categories: [anecdote]` and `tags: [anecdote]`, because the category controls the triggering-content warning. Use page bundles (`directory/index.md`) when a page owns images or downloads. Every image needs meaningful alt text; use the repository’s `figure` shortcode. [anchor: content/faq/contributing.md, content/anecdotes/, content/tips/, themes/hugo-xmin/layouts/_partials/page_meta.html, themes/hugo-xmin/layouts/shortcodes/figure.html]

Content structure is part of the reading UX: place `{{< back_to_top >}}` after level-2 headings and `{{< end_section >}}` at the end of deeper sections. Cross-references use Hugo `ref` shortcodes and the repository’s basename conventions. [anchor: themes/hugo-xmin/layouts/shortcodes/back_to_top.html, themes/hugo-xmin/layouts/shortcodes/end_section.html, content/faq/contributing.md]

## Rendering and search

`hugo-xmin` is not a pristine upstream dependency: treat `themes/hugo-xmin/` as application code. `single.html` composes header, metadata, searchable main content, equivalence injection, filters, Markdown content, automatic changelog, and footer. The related-pages partial uses tag intersections and defaults to five results. The separate `hugo-admonitions` theme supplies blockquote-alert rendering and Sass styling. Raw HTML is enabled in Goldmark, so changes to markup can affect accessibility and search. [anchor: themes/hugo-xmin/layouts/single.html, themes/hugo-xmin/layouts/_partials/related.html, themes/hugo-admonitions/layouts/_default/_markup/render-blockquote-alert.html, config.toml]

Search is a post-build concern. Hugo emits the search page and vocabulary asset; Pagefind scans the rendered HTML and creates `/pagefind/`. `data/equiv.toml` defines explicit synonym/equivalence classes, injected into searchable page content and vocabulary—there is no automatic singular/plural normalization. `search_terms` is an optional front-matter escape hatch for terms absent from visible prose. [anchor: bin/build.sh, themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/layouts/index.searchvocab.json, themes/hugo-xmin/layouts/_partials/equiv-inject.html, data/equiv.toml]

## Build and deployment

The production pipeline is intentionally self-contained: `bin/build.sh [output-dir]` runs the vendored Hugo 0.155.3 with garbage collection/minification, then the vendored Pagefind binary. Netlify publishes `public/` using that script; production timezone is configured separately. [anchor: bin/build.sh, netlify.toml, config.toml]

For ordinary editing, `bin/dev.sh [port]` runs Hugo against the working tree with drafts enabled and live reload, but search is inert because Pagefind is not run. Use `bin/preview.sh` for a real HTTP, searchable build in `/tmp/accessible-tips-preview`; it does not touch `public/`. A nonnumeric first argument previews a committed branch in the detached `_preview` worktree. Clean either mode with `bin/end-preview.sh`. [anchor: bin/dev.sh, bin/preview.sh, bin/end-preview.sh]

Generated output belongs in `public/` and should not be treated as source. Use the vendored binaries rather than assuming a system Hugo or Node toolchain. [anchor: bin/hugo-0.155.3, bin/pagefind, .gitignore]

## High-risk maintenance points

Most site-wide behavior lives in `config.toml` and the customized `hugo-xmin` layouts/partials, especially `header.html`, `page_meta.html`, `single.html`, search scripts, and `style.css`. Analytics is hard-coded in the header; Git revision display depends on GitInfo and is not guaranteed by current production configuration. Check the actual config before “fixing” apparent template assumptions. [anchor: config.toml, themes/hugo-xmin/layouts/_partials/header.html, themes/hugo-xmin/layouts/_partials/footer.html, themes/hugo-xmin/assets/js/search-page.js]

When changing search, test with `bin/preview.sh` over HTTP, not `file://` or `bin/dev.sh`. When changing front matter, verify both rendered metadata and search facets/equivalence behavior. Preserve accessibility details—alt text, labels, live regions, and the admonition markup—when editing templates. [anchor: bin/preview.sh, themes/hugo-xmin/layouts/_default/search.html, themes/hugo-xmin/layouts/_partials/search-filters.html, themes/hugo-xmin/layouts/_partials/equiv-page-inject.html]
