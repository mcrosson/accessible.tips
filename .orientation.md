# accessible.tips — orientation

A zettelkasten-style accessibility knowledge base built with Hugo (the
`hugo-xmin` theme is vendored locally and heavily customized) and hosted on
Netlify. Almost everything in this repo is markdown content; the "code"
surface is small and lives almost entirely in the theme and a handful of
`config.toml` knobs.

## Repo layout

- `config.toml` — single Hugo config, no environment overlays.
- `content/{tips,posts,faq,anecdotes}/` — the four content sections. There
  is no other top-level content bucket; do not invent one.
- `content/tips/_template.md` and `content/faq/_template.md` —
  copy-from-these starting points. `_example.md` is the same idea but live.
- `themes/hugo-xmin/` — vendored theme. Treat it as a real, customized
  codebase, not upstream; layouts and partials are heavily edited.
- `static/` — favicons, `site.webmanifest`, `uploads/`.
- `bin/hugo-0.155.3` — Linux Hugo binary. `bin/env.ps1` is a PowerShell shim
  that is **stale** (points at a non-existent `hugo-0.128.2.exe`); on Linux
  run `./bin/hugo-0.155.3` directly.
- `public/` — generated output, gitignored.

## File / page naming

- Tips: `[category]-[title].md`, e.g. `organizers-bujo.md`. The `[category]`
  prefix must match the page's primary `categories` entry. Underscores and
  camelCase are explicitly rejected (`content/faq/contributing.md`).
- Posts: `yyyy-MM-dd-title.md`.
- Anecdotes: `[author]-[title]-NNNN.md` with a left-padded 4-digit serial.
- FAQ: title-only `.md` files.
- Image-heavy content uses **page bundles** (`tip-name/index.md` plus
  assets alongside). Plain `tip-name.md` pages cannot have a sibling image
  directory referenced by `{{< figure >}}`.

## Frontmatter contract (the part contributors actually break)

Required on every content page (`content/tips/_template.md`):

- `title`, `authors` (list — single string also works), `publishDate`,
  `lastMod` (must be updated on every edit; should match the new changelog
  date), `toc`, `draft`, `categories` (list), `tags` (list).
- `changelog`: list of `{date, text}` entries. At minimum, an "Initial
  creation" entry is required. The "Changelog" section on the rendered page
  is **auto-generated from frontmatter** by
  `themes/hugo-xmin/layouts/single.html` — do not also write a hand-authored
  `## Changelog` heading or you'll get two of them.
- `toc: true` is required whenever the page has sections beyond the
  auto-rendered Changelog. `back_to_top.html` keys its label ("Back to ToC"
  vs "Back to top") off this flag.

Hard rules from `content/faq/contributing.md`:

- **One** primary category per page. Hugo folders don't allow more, and the
  site enforces this socially. Use a tag for cross-cutting topics.
- Anecdote pages **must** have `categories: [anecdote]` and
  `tags: [anecdote]`. The "WARNING: triggering" banner in
  `themes/hugo-xmin/layouts/_partials/page_meta.html` keys off the
  `anecdote` category — getting categories wrong silently suppresses it.
- FAQ pages: tag only with `faq`. News posts: no tags at all. Both are
  kept deliberately independent of the main knowledge base.
- Tags that conflict with access needs must use the form
  `conflicting-need-<need>` (e.g. `conflicting-need-low-vision`).
- All images must have `alt` text. Use the `{{< figure >}}` shortcode —
  its `alt` and `caption` params map directly onto `<img alt>` and
  `<figcaption>`.

## Shortcodes and content idioms

Three shortcodes, all in `themes/hugo-xmin/layouts/shortcodes/`:

- `{{< back_to_top >}}` — put on the line after every `##` heading.
- `{{< end_section >}}` — close out `###` and deeper sections; also adds an
  `<hr/>`.
- `{{< figure src="..." alt="..." caption="..." >}}` — Hugo's **built-in**
  figure shortcode. The theme's `_partials/figure.html` is a
  hugo-easy-gallery partial that is **not** wired into `shortcodes/`, so
  its `caption-effect`, `gallery`, etc. params do nothing here despite what
  the contributing guide implies. Stick to `src`/`alt`/`caption`.
- Cross-references: `[text]({{< ref "category-file" >}})`. The format is
  hyphen-prefixed file basename, no `.md`, no leading folder — e.g.
  `{{< ref "faq-contributing" >}}` (see `content/tips/digital-handwriting.md`).

## Theme and config sharp edges

- `themes/hugo-xmin/layouts/single.html` is the page template; it wraps
  `page_meta.html`, `.Content`, then the auto-Changelog block, then
  `footer.html`. `page_meta.html` is also where the page-menu "Jump to ..."
  links and the anecdote warning live — most rendering decisions a new
  contributor might want to change are in these two files plus
  `_partials/categories_tags.html` and `_partials/related.html`.
- `themes/hugo-xmin/layouts/_partials/related.html` shows up to 5 pages
  whose tags intersect this page's. `related_content_limit` is the config
  knob and is not set in `config.toml`, so it defaults to 5.
- `themes/hugo-xmin/layouts/_partials/header.html` hard-codes Plausible
  analytics pointed at `kb.accessible.tips`. There's no toggle; if you
  need to change or disable it, edit the partial.
- `footer.html` renders a per-page commit-revision link, but
  `config.toml` sets `enableGitInfo = false`, so `.GitInfo` is always
  empty in production. Netlify builds also don't enable it. Don't rely on
  the revision link appearing.
- `config.toml` has a real typo: `[markup.highlilght]` (sic). The
  `codeFences = false` it tries to set is therefore ignored. Code blocks
  in `content/tips/_example.md` and elsewhere render with default Goldmark
  behavior; do not assume syntax highlighting is configured.
- `config.toml` sets `[markup.goldmark.renderer] unsafe = true` — raw HTML
  in markdown is allowed site-wide. Load-bearing for the embedded
  `<span class="figure-number">Figure N: </span>` markup inside figure
  captions in several tips.
- `[outputs] home = ["HTML", "RSS", "JSON"]` is on, so a JSON index of the
  whole site is published at `/index.json`. Don't break it by changing
  home outputs without checking downstream consumers.
- `config.toml` declares `ignoreFiles = [ '.gitignore', '.gitkeep' ]` —
  add new ignore patterns here rather than scattering `.gitkeep` files.

## Hosting and editorial pipeline (context only)

Single-operator site. `content/faq/transparency-report.md` is the
authoritative note on who controls the hosting, domain, and source. Netlify
builds from `main` (`netlify.toml`; Hugo `0.155.3`). Decap CMS is listed in
`content/faq/tech-used.md` but the web editor is presently **not** supported
for editing — prefer text editor + git or the GitHub web editor (per
`content/faq/how-this-site-is-hosted-and-managed.md`).
